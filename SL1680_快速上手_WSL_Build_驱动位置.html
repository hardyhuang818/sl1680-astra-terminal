1怎么打开 WSL

SDK 装在 WSL 的 Ubuntu-22.04 发行版里（不是默认的那个）。任选一种方式进入：

方式 A：Windows Terminal / PowerShell（推荐）

wsl -d Ubuntu-22.04
# 进去后自动是 astra 用户，位于 ~ (/home/astra)
cd ~/sdk            # SDK 根目录

方式 B：开始菜单

开始菜单搜 “Ubuntu 22.04” 直接点开（如果装过图标）；或搜 “Terminal” 打开 Windows Terminal，点标题栏下拉箭头 ⌄ 选 Ubuntu-22.04。

方式 C：VS Code 远程（看/改代码最舒服）

# 在 WSL 里执行，需先在 Windows VS Code 装 "WSL" 扩展
cd ~/sdk && code .

方式 D：Windows 资源管理器直接看文件

地址栏粘贴：

\\wsl.localhost\Ubuntu-22.04\home\astra\sdk
小贴士：想让 wsl 不加 -d 也默认进这个发行版，执行一次：
wsl --set-default Ubuntu-22.04。关掉 WSL 释放内存：wsl --shutdown。

2怎么 Build

一键构建（推荐，脚本已封装所有修复）

# 在 WSL(Ubuntu-22.04) 里执行
bash "/mnt/d/Claude code/Case6_Astra/sl1680-scripts/build-sl1680.sh"

脚本自动做：source 环境 → 复用 sl2619 sstate 缓存 → 加 meta-tcm2-touch layer → 编译 openat2 seccomp wrapper（WSL2 pseudo 修复）→ 设 MTU 1280 → bitbake astra-media（带重试）。

手动分步（想理解每步时用）

cd ~/sdk
export MACHINE=sl1680 ACCEPT_SYNA_EULA=1
. meta-synaptics/setup/setup-environment      # 进入 build-sl1680/
bitbake-layers add-layer /home/astra/sdk/meta-tcm2-touch
bitbake astra-media
WSL2 三个必记的坑（脚本已处理，手动跑时注意）：
  1. build 前先 pkill -9 -f bitbake-server（daemon 缓存旧环境）
  2. 网络：sudo ip link set eth0 mtu 1280（否则大 git clone 会 TLS 断）
  3. tar 需走 openat2 wrapper：export PATH="/home/astra/toolwrap:$PATH"（否则 pseudo 报错，do_rootfs 失败）

只改了驱动/overlay 后增量重编（快）

cd ~/sdk
export MACHINE=sl1680 ACCEPT_SYNA_EULA=1
. meta-synaptics/setup/setup-environment
export PATH="/home/astra/toolwrap:$PATH"
bitbake -c cleansstate synaptics-tcm2 && bitbake synaptics-tcm2   # 只重编触摸模块
bitbake -c cleansstate astra-media && bitbake astra-media          # 重新组装镜像

产物在哪

~/sdk/build-sl1680/tmp/deploy/images/sl1680/SYNAIMG/

= 烧录工具要的 eMMCimg 目录。也已复制到 D:\Claude code\Case6_Astra\delivery_sl1680\SYNAIMG\。

3触摸驱动在哪

触摸驱动是我们从 synaptics_tcm2_touchcomm_tddi_v1.8.0.tar.gz 集成的独立内核模块（out-of-tree），编成 synaptics_tcm2.ko。

用途路径
Recipe（怎么编）~/sdk/meta-tcm2-touch/recipes-kernel/linux-drivers/synaptics-tcm2/synaptics-tcm2_1.8.0.bb
驱动 C 源码（tarball 解包后）~/sdk/build-sl1680/tmp/work/sl1680-poky-linux/synaptics-tcm2/1.8.0/synaptics_tcm2_touchcomm_tddi_v1.8.0/source/synaptics_tcm2/
驱动源 tarball（layer 里）~/sdk/meta-tcm2-touch/recipes-kernel/linux-drivers/synaptics-tcm2/files/synaptics_tcm2_touchcomm_tddi_v1.8.0.tar.gz
编出的 .ko~/sdk/build-sl1680/tmp/work/sl1680-poky-linux/synaptics-tcm2/1.8.0/image/usr/lib/modules/6.12.62/updates/synaptics_tcm2.ko
触摸 DT overlay（i2c0 @ 0x2C）~/sdk/meta-tcm2-touch/recipes-kernel/linux/files/dolphin-tcm2-touch-overlay.dtso
板子上的位置（烧完后）/usr/lib/modules/6.12.62/updates/synaptics_tcm2.ko
（开机 modprobe synaptics_tcm2 自动加载）

源码关键文件（在上面的 source/synaptics_tcm2/ 里）

syna_tcm2.c 主驱动syna_tcm2_platform_i2c.c I²C 层tcm/ 协议核心syna_tcm2.h 方向宏/开关

改方向（左右/上下反）、ENABLE_HELPER（唤醒自愈）等编译期宏 → 改 syna_tcm2.h；改 I²C 地址 / INT / RST GPIO → 改 overlay dolphin-tcm2-touch-overlay.dtso。

4显示驱动在哪

先分清楚：显示驱动 我们没写——它是 Synaptics 内核里自带的 syna_drm DRM 驱动。我们为这块 LVDS 屏只加了一个 DT overlay（配 1280×720 的 DSI 时序）。

A. 显示驱动本体（Synaptics 内核树内，已存在）

用途路径
DRM 驱动目录~/sdk/build-sl1680/tmp/work-shared/sl1680/kernel-source/drivers/synaptics/soc/berlin/modules/drm/
主驱动.../drm/drm_syna_drv.c
DSI panel.../drm/panel/panel_dsi.c
Bridge 胶水（LT9611 等）.../drm/bridge/syna_bridge.c · lontium-lt9611.c

B. 我们加的 LVDS 显示配置（overlay）

用途路径
1280×720 MIPI-LVDS overlay~/sdk/meta-tcm2-touch/recipes-kernel/linux/files/dolphin-td7800-lvds-overlay.dtso
注入 overlay 的 bbappend~/sdk/meta-tcm2-touch/recipes-kernel/linux/linux-syna_%.bbappend
base 板级 DTS（含原始 dsi_panel 节点，参考）.../kernel-source/arch/arm64/boot/dts/synaptics/dolphin-rdk.dts
编出的 .dtbo~/sdk/build-sl1680/tmp/deploy/images/sl1680/dolphin-td7800-lvds-overlay.dtbo
显示要改哪里？
• 改分辨率 / 时序 / DSI lane 数 / 颜色格式 → 改 overlay dolphin-td7800-lvds-overlay.dtso 里的 dsi_panel 时序块。
• 如果 MIPI转LVDS 转接板芯片需要 I²C/DCS 初始化（如 SN65DSI84 / LT8912 / TC358775）→ 需要在 .../drm/bridge/ 加 / 启用对应 bridge driver，并在 overlay 里加 bridge 节点。这取决于你转接板的芯片型号（待确认）。
