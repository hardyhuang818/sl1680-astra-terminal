SL1680 + DL7400 多屏启动命令手册

日期：2026-08-01　平台：SL1680 (Synaptics Astra Dolphin RDK) + DL7400
范围：接上 DisplayLink 多屏后，板上用什么命令启动 / 切换各 demo

0. 结论先行

硬规则：DLSDK 单进程独占。
同一时间只能有一个程序占着 DL7400。生产默认是 dl-face；要跑时钟、吞吐实测、读 EDID，必须先停它。

场景 命令 是否常驻
生产 UI（表情脸 + 字幕，多屏） systemctl start dl-face ✅ 开机默认自启
多屏时钟 + 跑马灯 systemctl stop dl-face && systemctl start dl-clock 手动启
多屏点亮 / fps 实测 systemctl stop dl-face && dl_multiscreen_demo 跑完即退
读 EDID 排查 systemctl stop dl-face && dl_edid 一次性
播视频到 DL 屏 systemctl stop dl-face && dl_player video.mp4 前台

一键全亮（所有已接屏显示时钟）：

systemctl stop dl-face 2>/dev/null
dl_clock --wait --fps 15 --speed 15 --max-hz 60

1. 连接后先确认

SSH 上板：

lsusb | grep -i 17e9          # 应能看到 DisplayLink (VID 17e9)
lsusb -t | head -40           # 确认 USB3：speed 应为 5000
systemctl is-active dl-face   # 生产界面是否已在跑
检查项 要求
USB 口 必须 USB 3.0。USB2 下 SDK 基本不驱动
线材 EVK 原生 USB3 上行最稳；零售坞经 C-to-A 线常只能到 USB2
显示器 一台屏只接一根线（别同时 DP+HDMI，会被枚举成两个假屏）
固件 SDK 通过 firmwarePath 自动保活/升级，一般不用手刷

2. 生产界面：dl-face（默认）

镜像里 开机自启。多屏时默认所有屏都是「表情脸 + 中英字幕」；可用文件或语音改角色。

2.1 启停

systemctl start dl-face
systemctl restart dl-face
systemctl stop dl-face
systemctl status dl-face
journalctl -u dl-face -n 50 --no-pager

服务实际执行：

/usr/bin/dl_face --max-hz 60 --fps 5 --wait --status /tmp/astra_status.txt
参数 含义
--max-hz 60 ★ 刷新率上限。别信 EDID preferred（有屏报 4K@160，会卡死）
--fps 5 UI 刷新率（表情/字幕够用）
--wait 开机时 DL7400 未枚举好就等，不直接退
--status PATH 读 astra_voice 写的状态文件，刷字幕
--screen N 只点第 N 块屏（省略 = 全部）

2.2 多屏角色切换（脸 / 摄像头）

控制文件：/tmp/astra_screen_mode.txt
格式：每行 屏号=角色

角色 含义
face 表情脸 + 实时字幕（默认）
camera C920 摄像头实况（看护监控） 
# 屏0 表情脸，屏1 摄像头
cat > /tmp/astra_screen_mode.txt << 'EOF'
0=face
1=camera
EOF

# 看当前角色
cat /tmp/astra_screen_mode.txt

# 全部回到表情脸
rm -f /tmp/astra_screen_mode.txt
# 或
printf '0=face\n1=face\n' > /tmp/astra_screen_mode.txt

dl_face 约每 150ms 读一次该文件，不用重启服务就会切角色。
语音「打开摄像头 / 关掉监控」等，本质也是写这个文件（astra_llm.py 本地拦截）。
文件在 /tmp，重启丢失 → 回到双表情脸（这是期望默认）。

2.3 只点某一块屏（手动前台）

systemctl stop dl-face
/usr/bin/dl_face --screen 0 --max-hz 60 --fps 5 --wait --status /tmp/astra_status.txt

3. 多屏时钟：dl_clock

演示用时钟 + 跑马灯。recipe 里 SYSTEMD_AUTO_ENABLE=disable，不会和 dl-face 抢设备。

3.1 推荐（systemd）

systemctl stop dl-face
systemctl start dl-clock
systemctl status dl-clock
journalctl -u dl-clock -n 40 --no-pager

切回生产：

systemctl stop dl-clock
systemctl start dl-face

3.2 手动前台（调试）

systemctl stop dl-face dl-clock 2>/dev/null
/usr/bin/dl_clock --wait --fps 15 --speed 15 --max-hz 60
参数 默认/建议 含义
--wait 开机自启必带 等设备枚举
--fps N 15 画面刷新
--speed N 15 跑马灯速度（字/秒）
--max-hz N 60 ★ 模式刷新率上限
--screen N 全部 只点第 N 块

每约 60s 日志会打各屏帧数：帧数在涨 = 链路通；帧数冻结 = 卡死；帧数涨但屏黑 = 显示器输入源没切对。

4. 多屏吞吐实测：dl_multiscreen_demo

回答「能带几块屏、什么分辨率、多少 fps」。推动态测试图，不是常驻 UI。

systemctl stop dl-face dl-clock 2>/dev/null

dl_multiscreen_demo                  # 默认每屏 120 帧动态画面
dl_multiscreen_demo -n 300           # 多推几帧
dl_multiscreen_demo -w 1920 -h 1080  # 强制分辨率
dl_multiscreen_demo -s               # 静态画面（标牌场景，编码很轻）
参数 含义
-n frames 每屏推多少帧（默认 120）
-w / -h 强制宽高（默认用屏 preferred，但内部仍应按 ≤60Hz 理解）
-s 静态模式：只推一次变化，模拟数字标牌

路径：/usr/bin/dl_multiscreen_demo
源码：meta-dlsdk/recipes-graphics/dl-multiscreen-demo/

5. 其它 DL7400 相关命令

5.1 读 EDID / 模式（排查「无信号」）

systemctl stop dl-face dl-clock 2>/dev/null
dl_edid

动线后屏序和模式号会变，必须重新跑 dl_edid，不要沿用旧编号。

5.2 播视频 / 图片

systemctl stop dl-face
dl_player /path/to/video.mp4

走 GStreamer 硬解 + 硬件缩放再推 DL 屏。全屏流畅视频在 4K 上大约只有个位数 fps，适合演示片段，不适合当视频墙。

5.3 设备卡死复位

进程被硬杀、没走 teardown 时，dlsdk_get_devices() 会一直返回 0。

# 推荐：按 VID 动态查找并 unbind/bind
/usr/bin/dl-clock-reset.sh

# 然后重新启服务
systemctl start dl-face
# 或
systemctl start dl-clock
复位方式 效果
echo 0/1 > authorized ❌ 救不回来
usb 驱动 unbind/bind ✅ 能救回来

6. 推荐操作顺序（接好多屏后）

# ① 确认 USB
lsusb | grep -i 17e9

# ② 生产多屏 UI（默认，通常已在跑）
systemctl restart dl-face

# ③ 可选：第二块改摄像头
printf '0=face\n1=camera\n' > /tmp/astra_screen_mode.txt

# ④ 若要做点亮 / 吞吐测试
systemctl stop dl-face
dl_multiscreen_demo -n 120

# ⑤ 若要看时钟墙
systemctl stop dl-face
systemctl start dl-clock
# 或: dl_clock --wait --fps 15 --speed 15 --max-hz 60

# ⑥ 测完回到生产
systemctl stop dl-clock 2>/dev/null
systemctl start dl-face

一键状态检查（仓库脚本，需自行 scp 上板）：

# tools/check_screens.sh
systemctl is-active dl-face
cat /tmp/astra_screen_mode.txt 2>/dev/null
lsusb | grep -i 17e9
for s in astra-voice astra-mode astra-translate dl-face vision-wake; do
  printf "%-18s %s\n" "$s" "$(systemctl is-active $s)"
done

7. 常见坑

现象 原因 处理
systemctl active 但屏全黑 两个 dlsdk 程序在抢；或设备卡死 只留一个；跑 dl-clock-reset.sh
get_devices 返回 0 被占用 / 卡死 / 非 USB3 stop 其它 dl-*；复位 USB；查 lsusb -t
帧数涨但屏黑 链路 OK，显示器输入源不对 用屏 OSD 切到正确 HDMI/DP
跑几帧就死卡 信了 4K@160 preferred 所有程序加 --max-hz 60
程序一退屏就黑 DLSDK 设计如此 生产必须 systemd 常驻
中文变方框 缺 CJK 字体 镜像需 ttf-wqy-zenhei
摄像头角色起不来 C920 被 vision-wake 等占用 systemctl stop vision-wake 后再切 camera
热插拔不自动亮 本板 hotplug 回调不可用 systemctl restart dl-face 重新枚举

8. 和「主板 HDMI demo」的区别

DL7400 路径 主板原生 HDMI
接口 DL7400 的 HDMI/DP 口 SL1680 板载 HDMI 口
软件 dl_face / dl_clock / dl_multiscreen_demo … sh /usr/bin/hdmi_demo.sh ai
机制 用户态 libusb 推像素（无 DRM 节点） DRM/KMS + Weston，满帧 60fps
桌面扩展 ❌ 不能把 Weston 扩过去 ✅ 就是本机桌面 
# 这是主板 HDMI，不是 DL7400
sh /usr/bin/hdmi_demo.sh ai     # gst-ai 图像分类 → 原生 HDMI
sh /usr/bin/hdmi_demo.sh ui     # Qt QML 演示

屏插错口是最常见的「怎么都点不亮」。
