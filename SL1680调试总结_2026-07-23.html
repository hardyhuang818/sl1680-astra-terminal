本地语音助手调通 + HT517 喇叭排障 + 语音音量

今日目标：完全甩掉 PC，实现"一台板子有网就跑"的本地语音助手（板载喇叭 + C920 麦 + 云端 DeepSeek 大脑），并解决喇叭出声、麦克风应答、音量控制。
2026-07-23 · SL1680 (Synaptics Astra "Dolphin" RDK)

一 · 问题与解决清单

1. 切换到完全本地模式（不用 PC）已解决

  • 停掉 PC 的 Docker 服务端 → 看门狗 astra-mode 自动切到本地模式 astra-voice。
  • 本地链路：C920 麦 → SenseVoice ASR（板上 CPU）→ matcha TTS（板上 CPU）→ DeepSeek（云端大脑）→ HT517 喇叭。
  • 板子直连 DeepSeek 验证通过。完全不用 PC，一台板子有网即可运行。

2.【今日主线】HT517 喇叭"没声 / 破音"大排查已解决 · 真凶＝接线

现象：喇叭时而没声、时而破音，结果飘忽不定（下午刚接好是干净的，后来越来越差）。

排查历程（走了弯路）：

  • 一度误判为软件：以为 I2S PRI SWITCH 被重置是 bug、加了 i2s-keepon 强行摁 ON（错误，已铲除）；又怀疑 asound.conf / alsactl。
  • 决定性判据：从板子端证明 数字通路 3/3 完全一致（DAPM 开关每次自动 engage、PCM 每次 RUNNING、零 XRUN），而听感却飘忽 → 数字侧稳定 + 模拟侧飘忽 ＝ 铁定物理/接线故障。
  • 真凶：① 功放 GAIN→GND 那根杜邦线断了（GAIN 悬空→增益乱套+时断时续，正是"结果飘忽"之因）；② Vin 只接了 3.3V（应接 5V）。
  • 解决：重接 GAIN→GND（换新线）+ Vin 挪到 5V → 声音正常。
教训：用户报硬件问题时，先让用户查接线/供电，别一头扎进软件。数字侧稳定 + 模拟侧飘忽 = 物理故障——这是最可靠的判据。

顺带解决的驱动坑：22050 采样率经 plughw 会触发内核 Oops（berlin_outdai_hw_params 空指针）卡死设备只能重启 → 用 ALSA plug 定义 astraout 强制 48000 绕开（必需；matcha TTS 是 22050）。

3. 麦克风不应答已解决

  • 现象：对着 C920 说话，助手没反应。
  • 根因：--min-rms 1000 门槛太高 —— C920 正常说话 RMS 只有 351~875，被判"太轻/太短"丢弃。
  • 解决：--min-rms 1000 → 300，麦增益 60% → 80%。

4. 音量太大 + 语音调音量已解决

  • dolphinasoc 是 dummy codec、无硬件音量控件 → 用 ALSA softvol 加 AstraVolume 控件到 astraout 链，开机默认 10%。
  • 语音调音量：patch astra_llm.py 加 try_volume() 拦截（改 Python 不重编译，有 .bak）——音量指令直接操作真实 AstraVolume，其它走 DeepSeek。
  • 可用指令：「现在音量多少」/「音量调到30」/「大声一点」/「小声一点」/「静音」。

5. 天气"没有联网" + 联网方案明天做

  • 现象：问天气，答"没有联网，查不到实时天气"。
  • 真相：DeepSeek API 是通的。但它是 LLM、无实时数据，系统提示词要求"不编造" → 如实说查不到（正确行为）。"联网"指实时数据能力 ≠ API 连接。音量之前答"50%"是它幻觉，已被 try_volume 拦截。

五 · 关键技术备忘（继续时必读）

  • astraout 必需：plug → softvol(AstraVolume) → plug强制48000 → hw:CARD=dolphinasoc,DEV=0。不能让 22050 直达硬件，否则 Oops 卡死。
  • I2S PRI SWITCH 是 DAPM 正常电源管理（空闲 OFF、播放自动 ON），不是 bug，别强摁（i2s-keepon 已 disable）。
  • ALSA 声卡号重启会交换（dolphinasoc 时而 card0 时而 card1）→ 一律用 CARD=名字。
  • softvol 值重启不持久 → 每次启动由 ExecStartPre astra_setvol.sh 10% 设。
  • 板端 SSH 192.168.5.126 root/1234；传文件用 PowerShell 调 board.py（Git Bash 会改写 /tmp）。
