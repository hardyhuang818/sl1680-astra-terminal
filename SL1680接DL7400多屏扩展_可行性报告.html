关于「如何更新固件」—— SDK 自动做了，不用手动刷

设备现在报告固件 12.3.26，正是 SDK 要求的版本。这是 SDK 自动升级的结果：

dlsdk_config cfg = {0};
cfg.size = sizeof(cfg);
cfg.firmwarePath = "/usr/share/displaylink/DL-firmware";  // ★ 指向 spkg 目录即可
cfg.embeddedMode = 0;
dlsdk_initialise_with_config(&cfg);   // 检测到固件不匹配 -> 自动升级 -> 设备重启

早期几次运行报「0 个设备」，就是 SDK 在后台完成固件升级（约 30s，设备会重启）。升级完成后即正常枚举。
固件更新的正确做法 = 初始化时把 firmwarePath 指向 spkg 目录，SDK 全自动处理。

排查中的两个教训（避免误导）

  1. snd-usb-audio 不是问题 —— DL7400 带 USB 音频，内核会自动绑 snd-usb-audio 到音频接口。曾误判为真凶，但实测证明：它绑着 SDK 照样正常工作，无需 unbind。udev 里只需要权限规则。
  2. USB 3.0 是硬前提 —— EVK 实测跑在 speed=5000 SuperSpeed。之前用零售 Anker 坞经 USB-C→USB-A 线只到 USB 2.0，SDK 直接不驱动。

「很多屏」

  • 本次只接了 1 台 HDMI 显示器 → display 数: 1。DL7400 有 4 个输出口，接满即 4 屏。
  • 多颗 DL7400 可同时挂：dlsdk_get_devices() 支持枚举多颗（C++ 封装自动扩容），无设备数硬上限（唯一上限 255 surface）。
  • → 很多屏 = N 颗 DL7400 × 每颗 4 屏，天花板是 USB3 带宽 + A73 CPU，不是 SDK。

2. 🔑 关键发现：DLSDK 是纯用户态，完全不碰内核

实测 libdlsdk.so(aarch64) 的动态依赖：

NEEDED: libusb-1.0.so.0     ← 唯一的外部依赖
        librt / libpthread / libstdc++ / libm / libgcc_s / libc
内部符号: core/sys/libusbbus/libusb/BusImpl_libusb10.cpp
          /dev/bus/usb/

没有 evdi、没有 DRM、没有任何 .ko。

DisplayLink 在 PC Linux 上的常规方案要装 evdi 内核模块 + DisplayLinkManager，移植到嵌入式很痛苦。
这个 SDK 完全绕开了它 —— 直接用 libusb 从用户态跟芯片讲话。

实际意义：SL1680 上不用改内核、不用重编 kernel、不用重刷 boot 分区。
甚至不用重刷镜像 —— 直接把 .so + demo scp 到运行中的板子就能跑。

3. 🔴 当前唯一阻塞：DL7400 没跑上 USB 3.0

实测到的现象

板子上 lsusb 能看到 DisplayLink：

Bus 001 Device 005: ID 17e9:7000 DisplayLink A83B3_A1

但 USB 拓扑暴露了问题：

Bus 001 (USB2.0 root hub, 480M) ← 所有东西都挤在这条 └─ 05e3:0610 SL1680 板载 Hub (USB2 面, 4口) └─ 2109:2822 Anker 坞的 USB2 Hub ├─ 17e9:7000 DisplayLink ← 480M, ver 2.10 ❌ USB2! └─ 291a:83b3 USB Billboard Device ← Alt-Mode 协商失败的标志 Bus 002 (USB3.0 root hub, 5000M) ← USB3 这条路上空空如也 └─ 05e3:0620 SL1680 板载 Hub (USB3 面, 4口) speed=5000 ⚠️ 下面什么都没挂

dmesg 里全是 new high-speed(=USB2)，一条 SuperSpeed 都没有。

这直接解释了「SDK 枚举到 0 个设备」

DL-7xxx 是 USB 3.x SuperSpeed 器件。在 USB2 下它只能枚举出来（所以 lsusb 看得到），但 SDK 拒绝驱动它 → dlsdk_get_devices() 返回 0。

不是驱动问题，是物理链路没跑起来。

板子这一侧是好的（已证明）

1-1 : 05e3:0610  USB2.1 Hub  480M   端口数=4
2-1 : 05e3:0620  USB3.2 Hub  5000M  端口数=4    ← 同一颗板载 Hub 的两张脸

同一颗 Genesys 板载 Hub 同时提供 USB2/USB3 通道，喂那 4 个 Type-A 口。
👉 4 个 Type-A 口每个都有 USB3 通道，不存在「哪个口才是 USB3」的问题。换口无用。

原因分析

那个 USB Billboard Device 是 USB-C Alt-Mode 才会出现的东西 → 说明 Anker A83B3 本质是 USB-C 坞。 用 USB-C → USB-A 线接到板子 Type-A 口时：

市面上绝大多数 USB-C 转 USB-A 的线只有 USB 2.0（哪怕线很粗）。真正 USB3 的 C-to-A 线是少数。

已换过一根线，仍是 USB2 → 判断为线的问题（目前手上没有支持 3.0 的 USB-A 转 C 线）。

⚠️ 退一万步：USB2 下 4K 本来就不可能

分辨率未压缩码率(RGB32)USB2.0 实际可用 ~40 MB/s
1080p60497 MB/s差 12 倍
4K601990 MB/s差 50 倍

所以 USB3 不是「优化项」，是「先决条件」。

4. ⚠️ 零售 Anker 坞 vs DL7400 EVK —— 固件不是一套

屏幕上出现的 「驱动版本过低，去 www.anker.com/83B3 下载」 是 DisplayLink 固件内置的「没装主机驱动」提示画面。

好消息：它能显示出来，说明坞有电 ✅、HDMI→4K 屏是通的 ✅、坞固件活着并在输出画面 ✅。

但它也暴露了：

固件配套驱动
零售 Anker 坞（手上这台）Anker 量产固件DisplayLink Manager（消费级，Win/Mac）
DL7400 EVK（明天到）SDK 固件 12.3.26DLSDK ✅ 我们集成的这套

SDK changelog 明写："Do not list devices with incompatible firmware"。
→ 所以 get_devices() 返回 0 可能有两个叠加原因：USB2 ＋ 固件不兼容。

⛔ 别去 anker.com 下那个驱动 —— 那是 Windows/macOS 的消费级驱动，SL1680 的 Linux 上完全用不了。

⛔ 不要给零售坞刷我们手上的 spkg 固件 —— 那 4 个（ella-dock / navarro-dock / ridge-dock / firefly-monitor）都是 DisplayLink 参考设计，不是 Anker A83B3。板型/DDR 配置不同，有刷砖风险。

官方 Linux 驱动 v6.2.0（2025-09）实测查证

  • ✅ DL-7xxx 已列入支持（v5.7 还没有，新版加了）
  • ✅ aarch64 有二进制（i686 / amd64 / armv7 / aarch64）
  • ✅ evdi 已验证到内核 6.15 → 6.12 没问题
  • ⚠️ 最多 2 个屏
  • ⚠️ 明确要求 "DisplayLink USB 3.0 devices"
反直觉的点：官方驱动反而能「扩展桌面」（SDK 做不到），但只能带 2 个屏（SDK 能带 4 个）。
两条路都要 USB3，所以 USB3 没通之前，装哪个都点不亮。

怎么选

  • 要多屏各显示各的内容（标牌 / 看板 / 内容墙）→ DLSDK，4 屏，零内核工作
  • 要把 Linux 桌面扩展到外接屏 → 官方 evdi 驱动，但只有 2 屏，且要编内核模块

6. 性能天花板（别按 Datasheet 规划）

DL-7xxx Datasheet 写的是 4× 4K@120Hz —— 那是芯片本身的能力，不是 SL1680 能喂饱的量。

瓶颈① USB 3.0 只有 5 Gbps（DL7400 支持 10 Gbps）→ 带宽砍半。

瓶颈② DL3+ 压缩跑在 SL1680 的 CPU 上 ← 真正的天花板
SL1680 = 4× Cortex-A73 @1.8GHz。SDK changelog 有 "Enable multi-threaded encoder on arm64 platform" → 编码是主机 CPU 软件做的。

但 DisplayLink 是按变化区域(delta)压缩的，画面不动的部分不重编码。
所以能带几个屏，取决于「内容动不动」，而不只是分辨率：

场景可行性
标牌/看板：多屏静态图文、局部刷新✅ 很轻松，4 屏 1080p 是甜点区
多屏 UI / 仪表盘：偶尔刷新✅ 可行
2 屏 1080p 视频播放⚠️ 需实测
4 屏 4K60 全动态视频❌ 不现实（带宽 + CPU 双杀）
