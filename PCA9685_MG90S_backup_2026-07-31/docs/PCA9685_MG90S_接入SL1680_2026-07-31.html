PCA9685 + MG90S 舵机接入 SL1680

日期：2026-07-31　平台：SL1680 (Synaptics Astra Dolphin RDK)
器件：PCA9685（16 路 12 位 PWM，I²C）+ MG90S（金属齿 9g 舵机）

0. 结论先行

2026-07-31 已实测跑通：舵机转动正常，I²C 通信、PWM 波形、板子电源全部验证过。 下文标 ★ 的地方是实测后修正的内容 —— 首版是接线前写的，其中地址部分推断错了。

能直接接，而且不需要电平转换 —— J32 上的 I²C 已经在板子内部过了 TXB0108（1.8V↔3.3V）， 引到排针的是 3.3V 侧。这跟 J32 上的 GPIO 不一样（那些是裸 1.8V，就是 TD7800 复位脚踩坑的原因）。

★ 但地址要改：PCA9685 出厂默认的 0x40 被板载的两颗 INA3221 电流监测芯片占了 （0x40 / 0x41，base DTS 里就声明的）。解法二选一：

  • 不动硬件：用 PCA9685 的 All Call 广播地址 0x70（ALLCALL 位默认开启）。脚本会自动退回到这条路
  • 改硬件：短接模块上的 A1 焊点 → 地址变 0x42，干净独立

先走用户态驱动（/dev/i2c-0 直写寄存器），不动内核、不烧录、不重启。 脚本已备好：sl1680-scripts/pca9685.py

1. 电气可行性核对

1.1 PCA9685（NXP datasheet Rev.3，Table 12/13）

参数 值 对我们的意义
VDD 供电范围 2.3 ~ 5.5 V 3.3V 合规；1.8V 不行（VPOR 上限就有 2.0V，可能出不了上电复位）
VIH（SCL/SDA/A0-A5/OE） 0.7 × VDD VDD=3.3V → 需要 ≥ 2.31 V
VIL 0.3 × VDD VDD=3.3V → ≤ 0.99 V
输入/输出耐压 5.5 V 容忍 5V 舵机信号回灌也不怕
LEDn 输出电流 单路 ≤ 25 mA，总 ≤ 400 mA 只驱动信号线，够用
默认 I²C 地址 0x40（A0~A5 全开路） ★ 撞板载 INA3221（见 §1.4）
All Call 广播地址 0x70（0xE0>>1，默认开启） ★ 地址冲突时的免焊接出路

1.2 SL1680 侧（RDK 原理图 SC950-000798-01 RevF，page 4）

原理图里 J32 那一页明确写着：

TXB0108DQSR          VCCA = 1.8V, VCCB = 3.3V
V1P8.TW0_SCL / V1P8.TW0_SDA     ← SoC 侧
V3P3.TW0_SCL / V3P3.TW0_SDA     ← J32 侧
R1740 2.2K_0402                 ← I²C 上拉

过了电平转换（有 V3P3. 网络）的信号：TW0_SCL/SDA、SPI2_*、I2S1_*、PDM_*、UART0_*、PWM1

没过转换（裸 1.8V）：GPIO36 / GPIO37 / GPIO38 / GPIO39、ADCI[0]/PWM[2]、ADCI[1]/GPIO2

这条正好解释了 7-28 那次 TD7800 触摸失效：J32.32(GPIO38)、J32.33(GPIO36) 是裸 1.8V pad， 去驱动 3.3V 域的复位输入，落在禁区里。I²C 没这个问题，因为它走了 TXB0108。

1.3 结论

检查 结果
PCA9685 能用 3.3V 供电吗 ✅ 2.3~5.5V 范围内
SL1680 的 I²C 能驱动它吗 ✅ J32 侧是 3.3V，VIH=2.31V 满足
会不会倒灌伤 SoC ✅ 不会，TXB0108 隔开了
地址冲突吗 ★ ❌ 0x40/0x41 被 INA3221 占用，见 §1.4
PCA9685 的 VCC 能接 5V 吗 ❌ 不行 —— 模块自带上拉会把 5V 灌到 TXB0108 的 VCCB(3.3V) 侧

★ 1.4 i2c-0 上已有谁（实测）

i2c-0 (= TW0 = J32.3/5)
  0x2c  UU   TD7800 TDDI 触摸       synaptics_tcm_i2c
  0x40  UU   INA3221 电流监测 #1    DTS: ina3221@40  (VCORE/VCPU/VDDM)
  0x41  UU   INA3221 电流监测 #2    DTS: ina3221@41  (PWR_3V3/VDDM_1V8/VDDM_1V1)
  0x45  UU   rpi_panel_regulator    遗留节点，未使用
  0x70  70   ★ PCA9685 的 All Call 广播地址

UU = 被内核驱动占用，用户态 ioctl(I2C_SLAVE) 会返回 EBUSY(16)。

地址方案：

A5..A0 跳线 地址 可用性
全开路（出厂） 0x40 ❌ 撞 INA3221 #1
短 A0 0x41 ❌ 撞 INA3221 #2
短 A1 0x42 ✅ 推荐
短 A2 0x44 ✅ 备选
不改，用 All Call 0x70 ✅ 免焊接，但只能写不能可靠读，且多块模块会一起响应

副产品：All Call 是个好用的接线自检手段。 接上电之前 i2cdetect -y -r 0 的 70 行是全 --， 接好之后会变成 70。不管默认地址有没有冲突，看这一格就知道芯片活没活。

另一个副产品：那两颗 INA3221 正好能监测板子电源轨。 实测舵机连续动作 12 秒期间 PWR_3V3 跌 0.24%、VDDM_1V8 跌 0.00% —— 板子电源全程稳定。 ⚠️ 读的时候只认有 label 的 in1/in2/in3（总线电压 mV）；in4/in5/in6 是分流电压(µV)， 会随负载大幅波动，别当成电压塌陷（我第一次就看错了）。

2. 接线表

2.1 信号与逻辑电源（接 J32）

PCA9685 模块 接到 SL1680 说明
VCC（逻辑电源） J32.1 或 J32.17（3.3V） ⚠️ 必须 3.3V，不能 5V
GND J32 任意 GND
SDA J32.3（TW0_SDA） 已过 TXB0108，3.3V 域
SCL J32.5（TW0_SCL） 同上
OE（使能，低有效） 悬空即可 模块内部已下拉到 GND = 输出使能。想做急停可接一个 GPIO
A0 ~ A5 ★ 建议短接 A1 → 地址 0x42 不焊也能用（走 All Call 0x70），见 §1.4

★ 若要给 OE 接 GPIO 做急停，不能用 J32 的 GPIO36/37/38/39 —— 那几个是裸 1.8V， 而 OE 的 VIH = 0.7×3.3 = 2.31V，推不动。要用 PWM[1]（J32.7，过了 TXB0108 是 3.3V 域）， 或者干脆软件 alloff 解决。

J32.4 有 5V，但不要拿它给舵机供电（见下）。

2.2 舵机电源（外供）

PCA9685 模块 接到
V+（舵机电源，绿色接线端子） 外部 5 ~ 6V 电源正极
端子 GND 外部电源负极，并与 SL1680 共地

为什么必须外供：MG90S 单只堵转电流约 700 mA ~ 1 A。16 路同时动就是 10 A 以上， 板子的 5V 引脚（J32.4）给不了，硬拉会把板子拽复位甚至烧走线。

电源建议： - 5V/3A 及以上开关电源（驱动 1~3 只 MG90S）；每多 2 只加 1A 余量 - V+ 端子处并一颗 1000 µF 电解（舵机启动瞬间电流尖峰会把电压拉塌，导致板子跟着重启） - 外部电源的 GND 一定要和板子 GND 接在一起，否则 PWM 信号没有共同参考电位

2.3 舵机接到 PCA9685

MG90S 三根线（见 MG90S/舵机引脚图.png）：

线色 含义 插 PCA9685 的哪一排
黄 PWM 信号 最上排（PWM，靠近芯片那侧丝印 PWM）
红 +5V 中间排（V+）
棕 GND 最下排（GND）

模块上 16 组 3 针，从 0 到 15。插反会烧舵机，插之前对一下丝印。

3. 驱动：先用户态

3.1 为什么不先做内核驱动

板子内核实测：

CONFIG_PWM=y
# CONFIG_PWM_PCA9685 is not set      ← 驱动没编
CONFIG_I2C_CHARDEV=y                 ← 用户态 i2c 可用

驱动源码 drivers/pwm/pwm-pca9685.c 在树里，开 CONFIG_PWM_PCA9685=m 就能编。 但那意味着重编内核 + 烧录 + 重启，而这块板的软复位不可靠，每次都要人工断电。 先用用户态把舵机转起来，验证接线和参数，之后再决定要不要上内核驱动。

然后转起来：

3.3 脉宽与角度的对应（MG90S 说明书）

脉宽 180° 舵机角度 360° 舵机 50Hz 下的 count
0.5 ms 0° 正向最大转速 102
1.0 ms 45° 205
1.5 ms 90° 停止 307
2.0 ms 135° 410
2.5 ms 180° 反向最大转速 512

资料里的 Arduino 例程用 60Hz + SERVOMIN 150 / SERVOMAX 600，换算过来是 612~2448 µs， 和说明书的 500~2500 µs 基本一致，只是两端各留了点余量。脚本默认 50Hz（20ms 周期，MG90S 标准）。

3.4 关键寄存器（脚本里已封装，排查时用得上）

寄存器 地址 说明
MODE1 0x00 bit7 RESTART / bit5 AI 自动递增 / bit4 SLEEP
MODE2 0x01 bit2 OUTDRV=1 图腾柱（舵机必须，开漏推不动）
LED0_ON_L 0x06 每通道 4 字节：ON_L, ON_H, OFF_L, OFF_H；通道 n 基址 = 0x06 + 4n
ALL_LED_ON_L 0xFA 一次操作全部 16 路
PRE_SCALE 0xFE 只能在 SLEEP 状态下写

PRE_SCALE = round(25MHz / (4096 × 频率)) − 1，50Hz → 121。 OFF 寄存器的 bit12 置 1 = 该路全关（输出恒低，舵机松力）。

4. 如果要上内核驱动（可选，后续）

好处是能走标准 /sys/class/pwm/pwmchipN/，也能被别的驱动（如 pwm-backlight、leds-pwm）引用。

改法：

  1. 内核 config 加 CONFIG_PWM_PCA9685=m
  2. dts 在 &i2c0 里加节点：
&i2c0 {
    pca9685: pwm@40 {
        compatible = "nxp,pca9685-pwm";
        reg = <0x40>;
        #pwm-cells = <2>;
        status = "okay";
    };
};
  1. 重编 + 烧录 + 断电重上，之后 /sys/class/pwm/pwmchipN/ 会出现 16 路

注意：内核驱动接管 0x40 之后，用户态脚本就绑不上这个地址了（ioctl(I2C_SLAVE) 会返回 EBUSY）。两条路线二选一，别同时用。

5. 排查清单

现象 先查
scan 什么都找不到 VCC(3.3V)/GND 是否接好；SDA/SCL 有没有插反。判据：i2cdetect -y -r 0 的 70 行——芯片活着就一定会出现 70（All Call）
★ ioctl EBUSY (16) 该地址被内核驱动占用。本板 0x40/0x41 是 INA3221、0x2c 是触摸、0x45 是遗留节点。新版脚本会自动跳过并退回 0x70
找到了但舵机不动 ① V+ 有没有外供 5V（最常见——VCC 和 V+ 是两路独立电源，只接 VCC 时 I²C 一切正常但舵机没电）② 舵机三线是否插反 ③ init 跑过没有
舵机抖动/嗡嗡响 电源电流不够 → 加大电源、V+ 并 1000µF；或脉宽超出行程顶死了，改回 500~2500 范围
一动舵机板子就重启 典型的电源塌陷 —— 舵机在从板子取电，或外部电源与板子没共地。可用板载 INA3221 佐证（见 §1.4）
★ 想停后台 loop 但 pkill 不存在 busybox 没有 pkill。用 python3 pca9685.py stop，或 ps \| grep xxx \| awk '{print $1}' 再 kill（注意排除自己的 PID）
角度不准 / 行程不满 每只舵机的实际行程有差异，调 US_MIN / US_MAX 两个常量标定
★ 想量信号确认有没有 PWM 万用表直流档量 CH0 信号脚对 GND：50Hz 下 0 度约 0.08V、180 度约 0.41V（3.3V×占空比）。恒 0V 或恒 3.3V 都说明输出侧有问题

6. 已确认 / 待确认

★ 已经实测确认的（2026-07-31）：

  • 3.3V 的 PWM 电平足以驱动 MG90S —— 首版把这条列为最大风险项，实测舵机转动正常， 不需要 3.3V→5V 缓冲。（原理：MG90S 标称 5V 信号但输入阈值通常低于 2.5V）
  • 板子电源不受影响 —— 舵机连续动作 12 秒，PWR_3V3 跌 0.24%、VDDM_1V8 跌 0.00%
  • I²C 加一个器件后通信稳定 —— 100kHz、上拉为板载 2.2k 与模块 10k 并联（约 1.8k）， VOL=0.4V 时灌电流约 1.6mA，在标准模式 3mA 上限内

仍待确认：

  • 挂多块 PCA9685 时，每块模块自带的 10k 上拉会继续并联。挂到第 4~5 块时总阻值接近 1kΩ， 灌电流逼近 3mA 上限，届时应去掉部分模块上的上拉电阻
  • 舵机数量、负载和外部电源规格，等确定机械方案后再定
  • 若最终要多路同时驱动，外部电源需按 单只 MG90S 堵转 0.7~1A 估算余量
