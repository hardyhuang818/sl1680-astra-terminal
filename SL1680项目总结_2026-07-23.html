一 · 项目是什么

在 Synaptics SL1680（4×Cortex-A73 + NPU）上做一台本地语音 AI 终端，配 DisplayLink DL7400 扩展多屏显示。

当前形态：不需要 PC。语音识别和合成全在板上跑，只有对话大脑走云端 DeepSeek。

功放/喇叭HT517I2S，dolphinasoc

⚠️ 板载麦克风 ZTS6672 有驱动层问题（i2s-mic1 时钟未使能），现用 C920 替代，需 Synaptics FAE 支持。

本版新增：麦克风等待守护

问题（2026-07-23 实测）：C920 挂的 1-1.3 总线会抖，实测掉线 86 秒。期间 astra_voice 每次启动都报 打不开 plughw:CARD=C920,DEV=0 (capture): No such device 退出，systemd 每 3 秒重拉一次，每次都白白加载 14–17 秒模型再死掉，连崩 7 次。

解法：ExecStartPre=/usr/bin/astra_wait_mic.sh C920 120 排在最前。两个设计要点：

  1. 按卡名判断而不是卡号 —— /proc/asound/C920 是按名字建的，卡号每次开机都会变（实测 C920 时而 card0 时而 card2）
  2. 要等到采集节点而不只是卡目录 —— 实测卡目录先出现，/dev/snd/pcmC<N>D0c 要等 udev 再建一会儿，中间那个窗口去开会报 No such file or directory

✅ 对抗性验证（整设备 unbind/bind 模拟真拔插）：

旧行为新行为
麦克风不在时崩 3 次 + 每次白加载模型activating，加载模型 0 次、报错 0 次、NRestarts 0
麦克风插回来—[wait-mic] C920 在第 17 秒就绪 → 加载一次模型 → 开始监听，NRestarts 全程 0

五 · 关键技术决策（都是踩出来的）

音频：astraout 是必需不是优化 ✅

Synaptics 驱动 berlin_outdai_hw_params 在非 48000 采样率（如 matcha 的 22050）下空指针崩溃，把播放子设备卡成占用、owner 是已死 PID，用户态无法释放，只能重启。

解法：/etc/asound.conf 定义 pcm.astraout = plug → softvol → plug(强制48000/2ch/S16_LE) → hw，硬件永远见不到 22050。所有 ALSA 寻址必须用 CARD=名字，索引 hw:0 会因声卡号重排而错。

显示：绝不能盲信 preferred_mode ✅

小米显示器 EDID 报 3840×2160@160Hz 为首选模式，DL7400 喂不动，dlsdk_display_show 永久阻塞（确定性卡在第 7 帧）。钳到 60Hz 立刻就好。

这个故障极像"显示器坏了/线坏了"，因为 EDID 是显示器的属性，跟着屏走。换线"没用"也是同一原因。

联网：智谱 chat 的 web_search 工具不工作 ✅

实测 prompt_tokens 只有 21、search_result 0 条，而模型照样编出一个气温（编 15~25℃/18~28℃，真实 28~36℃，两个模型还互相矛盾）。

正确做法是调独立搜索 API，拿到真实网页内容后配 GROUND_PROMPT（"只根据这些资料回答，绝对不许编造数字"）交给 DeepSeek。搜不到时，天气/股价这类硬实时问题直接说查不到，不回落。

误触发：纯能量门槛无解 ✅

实测办公室底噪 RMS 575~713，用户说话 RMS 470~1170——两者重叠。--min-rms 提到 1150 的代价是必须靠近麦（30cm 内）。

远场 + 嘈杂环境的根治方案是 KWS 唤醒词，还没做。

DL7400 断电不自愈的三个 SDK 缺陷

  1. dlsdk_register_hotplug_callback() 恒返回 DLSDK_UNSUCCESSFUL(2)，事件从未送达
    • ✅ 实测排除了平台原因（LIBUSB_CAP_HAS_HOTPLUG=1）
    • ⚠️ 但没有证明故障在 libdlsdk 内部——也可能是前置条件没满足或该配置本就不支持
  2. EDID / preferred_mode / display 数量全是缓存，屏断电了照样返回 SUCCESS
  3. ★致命：对已断开的 sink 调 dpaux_read，在有并发推帧时会让该 device 上所有输出一起黑屏
危险版本留档在 dl_face.c.DANGEROUS_dpaux_DO_NOT_BUILD，永远不要编进生产版。现行方案 = 语音说「重新检测屏幕」重启 dl-face 重新枚举。

构建期抓到的真 bug

编译层

  1. Yocto 硬关了 CMake 的 FetchContent —— cmake.bbclass 传 -DFETCHCONTENT_FULLY_DISCONNECTED=ON，sherpa 的第三方包全下不下来，configure 直接失败。症状酷似"网络不通"，但日志里根本没有 curl/HTTP/超时记录。解法：14 个包（含 4 层嵌套）走 SRC_URI 预取 → 拷进 ${S} 命中 possible_file_locations → 再关掉那个开关。⚠️ openfst/eigen 各有两个版本被不同子项目索要，都得备着
  2. -Werror=format-security —— espeak-ng 重设 C 标志丢了 -Wformat，剩下的 -Wformat-security 被 -Werror 变成致命错误
  3. 字体包名 —— 是 ttf-wqy-zenhei 不是 wqy-zenhei

打包层（都是"构建全绿、烧板才炸"那一类）

  1. 无 SOVERSION 的 .so 被丢进 -dev 包 —— 运行时镜像里根本没有这个库。SOLIBS=".so" / FILES_SOLIBSDEV="" 修复，已端到端验证（deb 里 4 个 .so 都在）
  2. 预编译 libonnxruntime.so 没被登记成符号版本提供者 —— RPROVIDES 显式声明
  3. 第三方装错位置 —— sherpa-onnx.pc 装到 ${prefix} 根下、cargs.h 装进 ${libdir}

镜像层（v2.6 验收时抓到，只看"构建成功"一个都发现不了）

  1. /etc/asound.conf 与 alsa-state 撞车 → do_rootfs 直接失败。删掉 alsa-state 那份 32 字节的占位注释
  2. dl-clock 和 dl-face 都自启 → DLSDK 单进程独占，两者抢 DL7400，表现为"屏幕黑着但服务 active"
  3. vision-wake 漏了自启 → 烧完的板子"人走近打招呼"不工作。⚠️ 这是我判断错了：以为它独占 C920，实际视频/音频是两个独立接口可以并存。应以板子实测状态为准，别按推测排除
  4. synap_cli_od 依赖没声明 → 碰巧 astra-media 已装，换个 image 就静默失效
SYSTEMD_AUTO_ENABLE:pn-<recipe> 写在别的 recipe 的 bbappend 里不生效 —— 这种 :pn- 覆盖只在 conf 文件（local.conf/layer.conf）里有效。必须改到该 recipe 自己里。

仓库 vs 板子

板子是真相，仓库历史上多次落后。曾出现：astra-voice.service 停留在旧硬件配置、astra_llm.py 四层能力一个都没有、5 个文件仓库里根本不存在、以及最危险的一次——板端回滚了会让两块屏全黑的代码但仓库源码没还原。

改完板子当场跑 tools/export_live.sh 导出回灌，用 backups/2026-07-23/DEPLOY_MANIFEST.txt 的 sha256 对照表验证一致。判断某个回退文件安不安全必须 diff 内容，不能看文件名。

六个反复踩的坑

  1. 上传会被注入 3 字节 UTF-8 BOM —— 文本没事，二进制直接废（Exec format error）。判据：板上大小 = 本地 +3
  2. .cmd 里绝不能写中文注释 —— cmd.exe 用 ANSI 代码页，中文变乱码并被当命令执行
  3. powershell -File 会把参数按空格重切 —— 外层引号保不住，-w / $(...) 被 PowerShell 抢去解析。把远端命令写成脚本文件
  4. busybox 缺项 —— 没有 install、timeout、base64、ldd；head 不认 -c/-12；wget -T 管不住 connect 挂起（用 curl -m）
  5. askpass 的子串匹配 —— findstr /C:"192.168.5.1" 会匹配上 192.168.5.126，把跳板密码喂给板子，只报 Permission denied 毫无线索
  6. 板上找 PID 别用 pgrep -f —— 会匹配到外层的 sh 自己
