0. 一句话

两条线都闭环了：TD7800 屏切到英文版 1280×720 专用排版（顺带挖出并修掉 PCA9685 地址误判）；EB7928 固件升级在 SL1680 上走 SPI 端到端跑通——452 页 / 7.4 秒， 比官方 MPC04+I²C 路径快约 8.5 倍。

1. Web 控制台英文版（commit 9c88f58）

  • 新增 /en 路由：英文版按 TD7800 实测 Set mode: 1280x720 定死排版整页不滚动 （量化验收：docH=720 / overflow=0 / 六卡片零裁切，含 coarse-pointer 放大后）； / 仍是中文宽屏版给 PC/手机，共用同一套 API；kiosk 的 cog 已指向 /en
  • 仪表盘改 6 列：板上是两颗 INA3221 = 6 条电轨 + 6 项系统指标 = 12 格正好 2 行 （5 列会排 3 行被 overflow:hidden 静默裁掉）
  • 触摸命中区用 ::before 撑到 62×34px 不占布局；垂直 pad 必须小于半个行距， ±11px 时相邻行 pad 重叠、后绘制者获胜，点开关底边会误触发下一个开关（实测抓到并修复）

2. 修掉一个真 bug：PCA9685 地址误判（同 commit）

接上 EB7928 EVK 后 i2c-0 冒出 0x44/0x47/0x48，旧判据「PRE_SCALE∈3~255 且 MODE1 bit1=0」 被 0x44 蒙混通过 → 舵机指令发给错的芯片 → Errno 121。改为核对出厂指纹 SUBADR1/2/3=E2/E4/E8 + ALLCALLADR=E0（只读指纹表定性：真芯片只在 All Call 0x70）。 经验已录：I²C 探测判据要用出厂指纹，不能用"寄存器值像不像"。

3. EB7928 FW 升级：SPI 端到端跑通（临时测试）

项 值
升级 PR4683565 → PR4684394（Build 0x0047772D → 0x00477A6A，identify 独立复核）
耗时 7.4 s（452 页，≈10 ms/页；官方 MPC04+I²C 63 s，快 ~8.5×）
主机侧 零硬件改动零重建：unbind ebi2c + debugfs pinmux 把 J32.24 片选还给 spi2
传输层 eb7928_spi.py 约 40 行换掉 I²C 后端，协议层 100% 复用 eb7928.py

三条路线的完整历程（各自死因都有价值）： 共用 i2c-0（死于 0x40 与 INA3221 冲突）→ 私有 I²C（死于 TXB0108 锁存拗不过 10K 上拉） → SPI（通，但最后一坑：主机接口类型由固件决定，不只是跳线——I²C 版固件下 SPI 全静默，换 SPI 通信版固件后立即通）。

新增诊断能力：实现显示寄存器读取——faildet（一键读全部显示失效检测寄存器） 和 dispreg <addr>（读任意显示寄存器），I²C/SPI 后端通用，已在板实测。 所用命令码与寄存器地址表出自 NDA 参考资料，细节仅存 Case61 本地文档，不入本仓。

4. 今日经验（新增三条）

  1. 主机接口类型（I²C/SPI）由器件固件决定，不只是硬件跳线——"读全 0"排查清单第 0 条
  2. 本内核 debugfs pinmux-select 是「组名在前 函数名在后」，与常见资料相反（EINVAL 陷阱）
  3. 复位后 1-2 秒离线读全 0 是器件重启常态——重试窗口给足（前两篇从抓包推出，今日亲测闭环）
