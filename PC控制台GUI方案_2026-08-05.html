SL1680 PC 控制台 GUI 方案

日期：2026-08-05　结论先行：可以做，而且不用装任何新东西。
板子上 python3 + systemd + 现成脚本已经覆盖了所有控制点，缺的只是一层"远程可点"的壳。

1. 三条技术路线对比

路线 做法 优点 缺点 判断
A. PC 原生程序包 SSH Windows 程序（如 PyQt）把按钮翻译成 ssh 命令 板子零改动 每台 PC 要装环境；每次点击开一条 ssh，慢（实测 1~2s/次）；密码管理麻烦 备选
B. 板端 Web 控制台 ★ 板子跑一个 python3 标准库 HTTP 服务（约 300 行，无任何依赖），PC/手机浏览器打开 http://192.168.5.126:8080 PC 零安装；手机也能用；一次开发到处用；实时状态推送容易 板子加一个 service（无依赖，风险极低） 推荐
C. 完整前后端框架 FastAPI/Vue 等 好看 板上没 pip，装依赖是大工程；杀鸡用牛刀 否

推荐 B 的关键依据（都是已验证的事实）： - 板上 python3 3.12.9 自带 http.server/json/subprocess，零依赖就能起 API 服务 - 所有控制动作板上已有现成命令（见 §2 清单），API 层只是薄薄一层转发 - 板子和 PC 在同一局域网（192.168.5.126），在外可走已有的 WireGuard - 前端单文件 HTML（我们已有同款样式体系），浏览器打开即用

2.6 状态仪表盘（只读，全部现成数据源）

指标 数据源
电源轨电压/电流 板载 INA3221（/sys/class/hwmon，PWR_3V3/VDDM_1V8 等 6 轨+电流）——舵机接入后看电源健康特别有用
服务状态灯 systemctl is-active ×5
CPU/内存/磁盘/uptime /proc
触摸活着吗 /proc/interrupts 中断计数增量
摄像头/麦克风在不在 lsusb + /dev/v4l/by-id
I2C 设备图 i2cdetect（触摸 0x2c / INA 0x40-41 / PCA9685 0x70）
最近对话 journalctl -u astra-voice 尾部（[你]/[机器] 行）

2.7 显示链路（应急按钮）

控制 背后命令 场景
重启 weston systemctl restart weston 桥片重新初始化，屏黑救急
面板 Display-On SPI 发 29h/11h（td7800_spi_tool.sh 现成） 复位后屏不亮
BIST 测试图 同工具 bist_on/off 排查"屏还是链路"问题

2.8 明确不放进 UI 的

  • 重启板子 —— 软复位不可靠（需人工断电），做成按钮只会造成"点了没反应"的误会；只放"需要断电重启"的提示
  • 烧录/内核操作 —— 风险高频次低，留在命令行
  • 板子密码修改等系统级设置

5. 与 Robot PDF 的衔接（为什么这个 GUI 值得做）

刚学的《Synaptics Tactile Tech for Robot》里，Synaptics 自家的灵巧手 PoC 就配了 "Software & GUI：rawdata 报告 / 力值输出 / 滑移检测 / 标定 + Visualization toolkit"—— 控制台+可视化是机器人演示的标配形态。

我们的板子已经是他们图里 "Astra Edge Compute + Actuator Ctrl + Camera/Mic 多传感器" 那一块 （SL1680 + PCA9685 舵机 + C920 + 麦克风）。如果后续拿到 SN6012T/CTS 触觉模块（SPI/I2C，3.3V， 正好 J32 还有空闲的 SPI2_SS1n/SS3n），这个 Web 控制台就是现成的触觉数据可视化载体—— 加一个 /api/tactile 端点画 5×12 力值热力图即可，和他们 Coralboard 上的 GUI 对标。
