一 · 原理图告诉我们的硬件底子

1.1 关键架构：载板 + 核心板 已核实

RDK 是两层：SoC / DRAM / eMMC 全在核心板上，经 260-pin（DDR4-SODIMM 形态）金手指 J29 插到载板。载板兼容 SL1680/1640/1620 三款核心板。载板暴露什么接口，SL1680 就有什么能力边界。

1.2 载板接口全清单 已核实

接口规格页意味着

两个此前没写进任何报告的硬结论：

① 载板没有音频 codec、没有麦阵、没有功放、没有耳机孔——只有数字 I2S×3 + PDM 排针。现在用 USB 声卡（C920 麦 + USB 耳机）不是将就，是这块板唯一免焊接路径；产品化要么加 I2S codec 小板，要么走 HDMI 音频。

② 载板没有 SD 卡槽、没有 SoC 用的板载 flash（唯一一颗 SPI-NOR 是 USB hub 的配置芯片）；系统只能在核心板 eMMC 上，外扩存储走 USB。

1.3 显示扩展硬件的真实形态 已核实

路径真实形态坑
J208 直连 DSI 屏22pin 里只有 3.3V；触摸 I2C 在 pin2/3；控制线来自 I2C GPIO 扩展器（非 SoC 直出）。官方验证过的直连屏只有 Waveshare 7" 800×480无 5V、无背光 PWM——5V 要从 40pin 排针 pin4/6 飞线
LVDS 屏（过桥）SL1680 无原生 LVDS PHY。LAMTL 板用 TC358775：DSI 4-lane@1Gbps 进，单链 LVDS ≤1600×1200、双链 ≤1920×1200@60（模块标称 1080p60）模块输入是 30pin FPC ≠ J208 的 22pin，需换线序转接；官方指南明确不覆盖这种接法
DL7400（USB 多屏）DisplayLink 四头 USB 图形芯片，自带 LPDDR4x 私有帧缓存（16Gbit）。每口都是 DP(4-lane)+HDMI 二合一（GPIO 上拉选模式）。上行 USB3 Gen1 5Gbps。芯片还引出 10G-Eth/RGMII/I2S（本卡未用）纯输出芯片，图纸上没有任何视频输入；手头图纸是 PCIe 卡形态，对 SL1680 走的是原生 USB3
Kbridge2/TD7800 子板SN65DSI85 的 DSI→双链 LVDS 桥 + 触摸 + 背光是单屏点亮/触摸固件烧录的工程台架，不是多屏扩展器，别和 DL7400 混

四 · 产品化前必须面对的硬边界

#边界细节
1NPU 只做视觉语音/LLM 全跑 A73 CPU；SyNAP 固定 shape、无 KV cache；Synaptics 自家语音示例也全是 CPU
2A73 无 dotprodint8 收益逐模型实测：SenseVoice 快 1.45×，VITS 反而慢 1.9×，别照搬
3TTS 授权全有雷espeak-ng GPLv3 静态穿透、matcha 模型无授权、melo 上游 AGPL；商用前必解
4DL7400 带宽天花板USB3 5Gbps 共享 4 屏；全动态视频 ~7fps；USB2 下 SDK 拒开；preferred_mode 是陷阱（4K@160 EDID 永久卡死链路，必须钳 ≤60Hz）
5触摸/LVDS 集成缺口两个 dtbo 编译进 /boot 但开机不应用（FIT image 无 overlay 清单），触摸 probe -22；触摸 INT 还是占位符；MIPI→LVDS 桥型号未定（TC358775 需 I2C 初始化，现在 dtso 假设免配置桥）
6板上无 docker/podmanFrigate（唯一原生吃 SyNAP 的成熟方案）、HomeAssistant 进不来，要加容器运行时或原生移植
7无真唤醒词、无 AEC现在"说话就应"+视觉唤醒；回声消除是土办法（播放时不采集）
8人脸识别整线模型全非商用授权 + 无 SyNAP 后端，产品化避开
9内存预算4GB 物理 → 可用 ~2.9GB；语音栈 ~415MB，多屏 UI + 常驻 LLM 要精打细算

五 · 一句话总结

SL1680 = 视觉 NPU 很强 + 4×A73 够跑本地语音 + 三路显示（HDMI 4K60 / DSI / USB 多屏）+ 双摄输入 + 完整 Yocto 工程链的边缘 AI 盒子。

它的本命是多模态对话终端和智能看护；它做不了的是视频墙、云端级大模型、以及任何绕不开授权雷的 TTS/人脸方案。硬件上音频必须外挂（USB/I2S/HDMI），存储只有核心板 eMMC，PCIe 只留给了 WiFi。
