2. ★别人能直接用吗？—— 不能，缺三样★

默认 astra-media 镜像 + DL7400 EVK 插上去 = 什么都不会发生。
系统不会多出 4 个显示器，weston 桌面也扩展不过去。

缺什么说明
libusb默认镜像没有（实测 find / -name "libusb*" 为空）。这是 DLSDK 唯一的外部依赖
DLSDK不在 Yocto 里，是 Synaptics 单独发布的 zip（需 NDA）。要自己打包进镜像
应用程序DLSDK 是"推像素"API，不是显卡驱动 —— 没有 DRM/KMS 节点。必须自己写程序渲染并调 display_show()，否则屏永远黑

关键架构认知

dlsdk_display_show(display, DLSDK_PIXEL_FORMAT_XRGB, pixels, stride);
                                                      ↑
                                          你自己准备好的像素 buffer
  • ❌ 不能把 Weston/Wayland 桌面扩展到这些屏（那需要 evdi 内核模块，且只支持 2 屏）
  • ✅ 每个屏画什么，由你的应用完全掌控 —— 对多屏内容墙反而正合适
  • 程序退出 = 释放显示 = 屏幕变黑（设计如此）。生产环境必须做成常驻服务

3. ★本 Case 的价值：趟平了 6 个会卡住好几天的坑★

价值不在"证明能接"（datasheet 早写了 4 口），而在这些只有真机才会暴露、且极难自行定位的问题：

坑① 绝不能盲信 dlsdk_display_preferred_mode() ← 最坑的一个

Mi Monitor 的 EDID 把 3840x2160@160Hz 报成"首选模式"。DL7400 + USB3(5Gbps) 根本喂不动 → wait_on_show 永久阻塞（确定性死卡：7 帧 / 18 帧，每次一模一样）。

为什么极难排查：EDID 是显示器的属性，所以故障会"跟着屏走" —— 换线、换端口、换到另一台机器，问题都跟着那台屏跑。这会让人 100% 误判成"这台屏坏了"或"这根线不行"。

📌 我自己就误判了：一度断言"Mi Monitor 的 HDMI 有问题"，还换过 4K HDMI 线（没用）、对调过端口。直到限制 60Hz 后瞬间正常 —— 同一台屏、同一根线、同一个口。HDMI 从来就没问题。

修复（pick_mode()）：从 dlsdk_display_modes() 里挑「与 preferred 同分辨率、刷新率 ≤ 60Hz 的最高刷新率」，找不到才退回 preferred。

坑② 进程被硬杀 → 设备卡死，且只有一种复位有效

没干净 teardown 就被杀 → dlsdk_get_devices() 一直返回 0 个设备。

复位方式效果
echo 0/1 > authorized❌ 救不回来
usb 驱动 unbind/bind✅ 能救回来
 
echo -n "2-1.4.1" > /sys/bus/usb/drivers/usb/unbind; sleep 3
echo -n "2-1.4.1" > /sys/bus/usb/drivers/usb/bind

不知道这条，会以为 EVK 坏了。设备路径会变（实测 2-1.4.1 → 2-1.2.1），所以复位脚本要按 VID 17e9 动态查找。

坑③ 同一台屏别同时接 DP + HDMI

会被枚举成两个独立 display（EDID 完全相同），其中一个还报出虚假的 160Hz，同时驱动互相打架。一台屏只接一根线。

坑④ auto-resize 默认开启 → 字体被放大 3 倍

overlay 以 640×480 为基准自动缩放：1920 宽 → ×3。写 216pt 实际渲染成 648pt，直接撑爆屏幕。→ 必须 auto-resize=false，此后 px = pt × 96/72。

坑⑤ 镜像里没有任何 CJK 字体

fc-list :lang=zh 为空，只有 Liberation。中文被 Pango 渲染成 Unicode 码点方框（591A=多、5C4F=屏…），看起来就是乱码。→ 加 ttf-wqy-zenhei（~14MB，meta-oe 现成）。

坑⑥ 软件缩放白吃 94% 的时间

4K→1080p 实测（150 帧）：

管线耗时帧率
纯硬解 4K VP91.35s111 fps ← 解码毫无压力
+ 软件 videoconvert/videoscale17.55s8.5 fps ← ❌ 浪费 94%
+ 硬件 synavideoconvertscale5.63s31.9 fps ← ✅ 快 3.7 倍

注意：synavideoconvertscale 只输出 RGB/BGRA/NV12/I420/YUY2 —— 没有 BGRx，用 BGRA（32bpp 布局与 DLSDK_PIXEL_FORMAT_XRGB 一致）。

4. ★方法论：判断"屏到底通没通"要看帧数，不能靠肉眼★

这是本 case 最有价值的一条经验。dl_clock 每 60s 打印各屏帧数：

现象含义解法
帧数冻结链路卡死降 Hz（坑①）/ USB 深度复位（坑②）
帧数在涨但屏黑链路正常，显示器输入源没切对按屏上 OSD 切 Input Source

两者原因和解法完全不同，混为一谈会浪费大量时间。

另两个坑：看日志要认准 PID（卡死的旧进程会留下误导性统计）；屏数和模式号会变（实测 2→3→4），动线后必须重新 dl_edid。

7. 扩展性

  • 一颗 DL7400 = 4 屏（已全部验证）
  • 多颗可同时挂：dlsdk_get_devices() 支持枚举多颗（C++ 封装自动扩容），无设备数硬上限（唯一上限 255 surface）
  • → 更多屏 = N 颗 × 4 屏，天花板是 USB3 带宽 + A73 CPU 跑 DL3+ 压缩，不是 SDK
