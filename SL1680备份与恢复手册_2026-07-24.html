二 · ⚠️ 三份镜像的关键区别

B（7-13）不能当作"当前功能的备份"。实测确认（解压 5.4 GB ext4，debugfs 读取）：
✗ /usr/bin/astra_voice        ✗ /usr/bin/dl_face
✗ /usr/lib/libdlsdk.so        ✗ /home/voice/
✓ /etc/asound.conf  32 字节   ← 只是 alsa-state 的占位注释

原因：语音终端是 7 月 18–23 日在板子上手工装的，从来没有被打进任何镜像。直到 A（7-24）才第一次进 Yocto 构建。

三 · 使用方法

A 烧新镜像（含语音终端）

# 1. 校验完整性
cd flash_image_20260723163055
sha256sum -c SHA256SUMS.txt

# 2. 板子进 USB 恢复模式（IO 板按钮位置见 D:\Astra\board_backup\*.png）
# 3. 用 usb-tool-astra-update-v2.0.1 烧录

烧完必须做两件事，否则语音助手起不来：

# 灌模型（见第四节）
# 填 API key
cp /etc/astra/llm.conf.sample /etc/astra/llm.conf
chmod 600 /etc/astra/llm.conf
vi /etc/astra/llm.conf
systemctl restart astra-voice     # EnvironmentFile 只在启动时注入

详见 flash_image_20260723163055\README_烧录说明.md。

B 回退到 7-13 干净底座

同样的烧录流程，把源目录换成 delivery_sl1680\SYNAIMG\。

烧完得到的是没有任何语音功能的系统。要恢复功能需要从 meta-dlsdk\ 重新构建（bitbake astra-media 就直接是 A 了）。

什么时候才该用 B：怀疑是新镜像本身把系统搞坏了、想验证"换回旧底座是否还有问题"。单纯想去掉语音终端的话，local.conf 里 ASTRA_TERMINAL_PACKAGES = "" 重新构建更干净。

C 还原成出厂 Yealink 状态

D:\Astra\board_backup\ 是逐分区 dump（partitions\p01~p18*.img.gz + GPT 头 + boot0/1），和 SYNAIMG 不是一个格式，恢复方法见该目录的 烧录指南_SL1680.md。

这份是"把板子还给 Yealink"用的，日常回退用不到。

D 恢复模型与配置（★ 每次烧完都要做）

# 传到板子（PC 上执行）
powershell -File tools\bput.ps1 backups\models_2026-07-24\voice_sv.tar.gz /home/voice_sv.tar.gz
# ...其余 7 个同理

# 板子上解压
mkdir -p /home/voice && cd /home/voice
for f in sv matcha tts kws bin scripts; do tar xzf /home/voice_$f.tar.gz -C /home/voice; done
tar xzf /home/voice_llm_inuse.tar.gz -C /home/voice
tar xzf /home/etc_astra.tar.gz -C /
chmod 600 /etc/astra/llm.conf
chmod +x /home/voice/*.py /home/voice/bin/*
systemctl restart astra-voice astra-translate dl-face
bput.ps1 会注入 3 字节 UTF-8 BOM，二进制传完必须剥掉（判据：板上大小 = 本地 +3）。更省事的办法：PC 上起 python -m http.server，板子上 wget 拉。

E 源码/工具/文档快照

backups\2026-07-23\ 里三个 SL1680_backup_v*.tar.gz 是配置文件级快照（19 项：etc/、systemd/、home_voice/、usr_bin/），另外三个是 meta-dlsdk\、tools\、文档的打包。

这些是 v2.1/v2.2/v2.4 时点的，现在仓库已经到 v2.6，直接用仓库当前版本即可。这些快照只在"想看某个时点长什么样"时有用。

六 · 已知缺口

  1. 板子当前状态（v2.4）没有整机镜像 —— 只在 eMMC 上。靠"源码 + 模型备份"可重建，但不是一键回滚
  2. 模型来源没记录具体 release URL —— README_models.md 写了是 sherpa-onnx 官方预训练包，但当初的下载链接没留。所以 D 这份备份不能丢
  3. 新镜像没在真板子上实烧验证过 —— 所有验证都在镜像文件层面（debugfs 直接读 ext4：文件在、服务自启配置对），"烧进去开机真能跑"这一步还没做

七 · 备份策略建议

  • 每次动板子之前，先跑一次 tools\export_live.sh 导出配置对比
  • 模型不会变，D 这份除非换模型否则不用重做
  • 镜像每次构建都换时间戳目录，旧的别急着删（磁盘 2 TB，不差这点）
  • etc_astra.tar.gz 单独管理，它是唯一含密钥的包
