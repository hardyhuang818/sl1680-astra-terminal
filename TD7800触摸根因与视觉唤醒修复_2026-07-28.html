1触摸：为什么最后确定是硬件

1.1 症状

  • I2C 地址 0x2c 能应答，驱动能读出固件 ID td7800-12.7.1
  • 但中断计数恒 0，ATTN(gpio586) 恒 in hi（IRQ 配 TRIGGER_LOW，等于芯片从不请求上报）
  • 每次断电重上表现都不一样：有时半死，有时完全不在 I2C 上
  • 显示侧一直正常

1.3 决定性的对照实验

gpio-dwapb 的 get() 读的是 EXT_PORT（真实焊盘电平），不是输出影子寄存器。 所以一条 out 线读出随机值，就说明焊盘根本没被驱动。

高速采样 60 次 @30ms：

gpio-516 LCD_RST  (STS1_VALD, hog out)  翻转25  ★飘★   ← 接到屏
gpio-518 TP_RST   (STS1_SOP , hog out)  翻转34  ★飘★   ← 接到屏
gpio-519 vol_down (STS1_CLK , in     )  翻转 0  稳定    ← 同组，没接出去
gpio-524 vmmc_sdhc(对照,     out     )  翻转 0  稳定
gpio-535 hdmitx5v (对照,     out     )  翻转 0  稳定

同一个 pmux 组、同一颗 portb 控制器，飘的正好是接出去到屏的那两条。指向电气而非配置。

1.4 万用表定性

脚实测判定
J32.32 TCH_RESET_N1.57V禁区
J32.33 RESET_N2.28V禁区，离 VIH 只差 30mV
J32.1 / J32.23.3V / 5V正常

TD7800B datasheet：

  • RESET_N / TCH_RESET_N 属 IOVCC 域（Table 44 第 6 项「System interface」）
  • IOVCC = 2.7 ~ 3.6V（Table 50）
  • VIH1 = 0.70 × IOVCC，VIL1 = 0.30 × IOVCC（Table 51）→ 3.3V 供电时合法高电平最低 2.31V，合法低电平最高 0.99V
核心矛盾 1.57V 和 2.28V 双双落在 0.99 ~ 2.31V 的禁区里 —— 芯片看到的既不是高也不是低。
而 SL1680 的 STS1_* 是 1.8V 域 pad，输出高最多 1.8V，物理上给不出 2.31V。

2.28V = 1.8V + 0.48V 正是 pad 上端 ESD 二极管的正向压降 —— 说明面板侧 3.3V 上拉在往 1.8V pad 里倒灌电流，被 ESD 结构钳位在 VDDIO + Vf。这是持续的潜在损伤路径。
前科 同一块板 7 月 27 日：TC358_RST / TC358_PWR_EN 接 3.3V，把 VCC1V8_LCM 顶到 2.38V。凡是 SL1680 直连面板的控制脚，都要先确认电压域。

1.5 决定性验证

拔掉 J32.32 / J32.33 两根杜邦线后：

触摸中断:  0  →  2626
dmesg:  syna_dev_process_unexpected_reset: Device has been reset  ×2

拔线产生的复位脉冲让触摸引擎活了，两次意外复位被自愈驱动接住（0 死锁）。假设成立。

这一条同时解释了所有此前想不通的现象：

  • I2C 从机块能应答固件 ID，但触摸引擎不跑 → 复位处于不确定态
  • ATTN 永远不拉低 → 引擎没启动
  • 每次断电重上表现都不一样 → 2.28V 离阈值只差 30mV，任何漂移都会翻
  • GPIO 读回来是 47% 占空的噪声 → 焊盘被外部拉扯，SoC 没能真正驱动

2视觉唤醒：服务在跑，但从不触发

2.1 症状

systemctl is-active vision-wake = active，但开机 30 分钟一条检测日志都没有，从未触发欢迎语。

2.2 根因

手动跑一次就暴露了：

$ synap_cli_od -m .../model.synap --score-threshold 0.4 /tmp/vw_270.jpg
E:SyNAP: InputData():102: Input file not found: /tmp/vw_270.jpg

把同一帧 cp 成稳定副本再推理则完全正常（Detection time: 52.95 ms）。

环节时间
multifilesink max-files=4 @ framerate=5/1一帧只活 0.8 秒
synap_cli_od 从 fork/exec 到真正打开输入文件要先加载 30MB 模型，接近 1 秒

正好卡在边界上 → 时灵时不灵，失败时静默返回空 → 框高为空 → pct = 0 → 永远达不到 45% 阈值 → 从不触发。

放大这个 bug 的是日志设计 心跳只在 pct > 0 时才打，所以"推理静默失败"和"确实没人" 长得一模一样 —— 30 分钟看不出异常。

2.3 修法

# 修前
OUT=$(synap_cli_od -m $MODEL --score-threshold 0.4 "$F" 2>/dev/null)

# 修后
cp "$F" /tmp/vw_cur.jpg 2>/dev/null || { sleep 0.3; continue; }
OUT=$(synap_cli_od -m $MODEL --score-threshold 0.4 /tmp/vw_cur.jpg 2>&1)
case "$OUT" in *"not found"*|*Error*) echo "[vwake] 推理失败(跳过): ..."; continue;; esac

外加：没人时也每 ~40 tick 打一条"在跑，当前无人"，让"在跑"和"卡死"可区分。

修完 5 秒内即报 [vwake] 框高=75% (阈值45%, armed=1)。端到端也跑通了：

[vwake] 框高=94%  →  astra_voice: [唤醒] 检测到有人靠近，播欢迎语
[vwake] 人已离开，重新武装
[vwake] 在跑，当前无人 (armed=1)          ← 新加的心跳
教训 任何"只在成功时才打日志"的循环，都会把静默失败伪装成正常运行。

3触摸驱动：ISR 上下文死锁

内核报：

INFO: task irq/49-synaptic blocked for more than 983 seconds

syna_dev_process_unexpected_reset() 在中断线程上下文里同步调用 dev_set_up_app_fw()，而后者要走 I2C 并拿 mutex → IRQ 线程被永久卡住。

补丁（60 行，meta-tcm2-touch/.../0001-enable-helper-and-fix-isr-deadlock.patch）：

  1. syna_tcm2.h：/* #define ENABLE_HELPER */ → #define ENABLE_HELPER
  2. syna_tcm2.c：
#if defined(ENABLE_HELPER)
    if (!tcm->helper.workqueue)
        tcm->dev_set_up_app_fw(tcm);
#else
    tcm->dev_set_up_app_fw(tcm);
#endif

有 workqueue 就交给 helper，没有才保持原行为。

实测有效 拔线产生的那两次意外复位就是它接住的，0 死锁告警。

版本做法结果

7待办：硬件

7.1 现状的风险

复位脚现在硬接 3.3V，能跑但上电不保证稳。

datasheet Table 57 要求上电复位低电平宽度 tRW1 ≥ 3000µs （Figure 32：RESET_N / TCH_RESET_N 在 IOVCC/VCI/LVDSVCI 爬升期间必须保持低）。 直连 VCC 时复位与电源轨同时上升，低电平宽度 ≈ 0 → NVM 加载可能不完成 → 上电黑屏 / 触摸不上 I2C。

现场应急（不用改焊接）：

  1. 软件路线：weston 重启（触发 modeset → VPP 重发 TC358775 初始化）+ SPI 发 29h Display-On、11h Sleep-Out
  2. 硬件路线：拔掉两根复位线 → 等 2~3 秒 → 先插回 J32.32（TP_RST）→ 停 1 秒 → 再插 J32.33（LCD_RESET）
⚠ 安全提醒 复位线直连 3.3V 时绝不能碰 GND —— 那是直接短路电源。

7.2 短期正解：RC 上电延时

3.3V ──[ 10k ]──┬── 复位脚 (J32.32 / J32.33)
                │
              [ 1µF ]
                │
               GND
  • τ = 10k × 1µF = 10ms，爬到 VIH(2.31V) 约需 12ms， 对 tRW1 ≥ 3ms 有 4 倍余量
  • 要让 LCD_RESET 比 TP_RST 晚 10ms，把 J32.33 那颗电容换成 2.2µF（约 26ms）
  • 加了 RC 之后这两根线才可以安全地碰地做手动复位（电流被 10k 限住）

7.3 长期正解：电平转换

要把复位交回 SoC 用软件精确控时序，必须先加 1.8V → 3.3V 电平转换：

  • 推荐 74LVC2T45（VCCA=1.8V、VCCB=3.3V、 DIR 固定 A→B），双通道正好两条线，推挽输出顶得住面板上拉
  • 或每条线一颗 2N7002 + 10k 上拉到 3.3V
  • ❌ 不要用 TXB0102 / TXS0102 —— 自动方向器件驱动能力弱，会被面板侧上拉误判方向

装好后按 Table 57 做时序：上电复位低电平宽度 tRW1 ≥ 3ms， LCD_RST 比 TP_RST 延后 10ms 释放。

7.4 顺带要查的

TD7800 的 TCH_IO_SCL / TCH_IO_SDA 也在 IOVCC(3.3V) 域 （Table 44 第 6 项）。目前 I2C 能通，说明总线上拉在 3.3V —— 也就是说 SL1680 的 1.8V I2C pad 一直在承受 3.3V。虽然一直没出问题，但属于同一类隐患，做板时应一并处理。

8本次的操作失误（记录以免重犯）

失误后果教训
裸读 /dev/mem 的 pinctrl 寄存器区（0xf7ea8000） 内核挂死，只能断电重上 这类寄存器有访问保护或需先使能时钟；看 pinmux 用 /sys/kernel/debug/pinctrl/*/ 就够，零风险
明知 unbind/rebind 路径不可靠，仍跑了第二次 触摸刚恢复（2626 中断）又被打断，probe 走不完 这个驱动 rebind 时 probe 不完整；要重置驱动用模块重载，别用 sysfs rebind
rmmod 在已损坏状态下调用 segfault，模块卡在半加载态，只能重启 驱动已处于异常状态时不要再叠加操作
用 git diff 生成 Yocto 补丁 只出 70 行（应为 248），差点把完整补丁覆盖成增量 do_patch 会把补丁提交进 kernel-source 的 git HEAD； 必须对原始基线做 diff 并重放验证

9可复用的方法（金手法）

  1. pad↔GPIO 标定：找一个已知能稳定驱动的脚反推 bank 起始号，别靠注释推。
  2. 判断焊盘有没有被真正驱动：gpio-dwapb 的 get() 读 EXT_PORT （真实焊盘电平）。一条 out 线读出随机值 = 焊盘没被驱动。配合"同组没接出去的线作对照"， 能一眼分开配置问题和电气问题。
  3. 电平域快速判据：读数 ≈ VDDIO + 0.5V → 高压侧上拉在往低压 pad 倒灌， 被 ESD 二极管钳位。
  4. 补丁重放验证：patch --dry-run 后 cmp，确认 "基线 + 补丁 == 当前源码"，避免补丁悄悄失真。
  5. 静默失败的识别：服务 active + 零日志 ≠ 正常。任何只在成功路径打日志的循环 都要补一条"我还活着"的心跳。
