4.5 幻觉抑制（技术亮点）

实测发现：某国产大模型的"联网搜索"工具并不真正工作 —— 返回搜索结果 0 条，但模型照样编造出一个气温（编 15~25℃ / 18~28℃，真实 28~36℃，且两个模型互相矛盾）。

我们的做法：改调独立搜索 API 拿到真实网页内容，再配"只根据这些资料回答，绝对不许编造数字"的接地提示词。搜不到时，天气 / 股价这类硬实时问题直接说查不到，不回落。

效果：实时数据问答零编造。

七 · 关键技术结论（供内部复用）

7.1 DL7400 集成

  1. DLSDK 是纯用户态 libusb，无需内核模块，meta-dlsdk 直接编译即可
  2. 必须 USB 3.0 —— USB 2.0 下 SDK 直接拒绝驱动
  3. 绝不能盲信 preferred_mode —— 某显示器 EDID 报 4K@160Hz 为首选，DL7400 喂不动，推屏永久阻塞。必须钳制 ≤60 Hz
  4. DLSDK 单进程独占 —— 一个进程握着设备，第二个进程枚举到 0 个
  5. 不能把桌面扩展到这些屏 —— DLSDK 是"推像素"API，没有 DRM/KMS 节点，必须自己写程序渲染。对内容墙场景反而更可控

7.2 判断"屏到底通没通"要看帧数，不能靠肉眼

现象含义解法
帧数冻结链路卡死降刷新率 / USB 深度复位
帧数在涨但屏黑链路正常，显示器输入源没切对按屏上 OSD 切 Input Source
两者原因和解法完全不同，混为一谈会浪费大量时间。

7.3 语音侧

  1. NPU 只对视觉有用 —— 语音链路全在 CPU（Synaptics 自己的语音示例也是）
  2. 量化收益因模型而异，必须逐个实测（SenseVoice int8 快 1.45×，但 VITS int8 反而慢 1.9×）
  3. 纯能量门槛无法区分人声和环境噪音 —— 实测办公室底噪 RMS 575~713，人声 470~1170，两者重叠。远场场景根治方案是唤醒词

DL7400 断电不自愈问题（已提报厂商）

实测发现 SDK 三个层面的问题，已写中英双语报告：

  1. 热插拔回调注册恒失败，显示器接入 / 移除事件从未送达
  2. EDID / 首选模式 / 显示器数量全是缓存，屏断电了照样返回成功
  3. 唯一能反映现实的 AUX 读取接口，在并发推帧时会让该设备所有输出一起黑屏
结论：SDK 层面目前没有安全的在线检测手段。

九 · 商业化定位建议

适合

  • 多屏数字标牌 / 商场导购屏 / 展厅内容墙
  • 语音交互终端（前台接待、导览、智能看护）
  • 低变化内容的多屏仪表盘 / 监控看板

不适合

  • 视频墙 / 多路视频监控回放（帧率不够）
  • 需要桌面扩展的办公场景（DLSDK 不提供 DRM/KMS）
成本优势：一颗 SL1680 + 一个 DL7400 即可驱动 4 屏，且语音 AI 全部端侧运行（仅对话大脑走云端），无需 GPU 或额外 PC。
